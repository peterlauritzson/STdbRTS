## Where the game is

An original browser RTS converging on the Honey Badger mod's strategic
identity. Rust simulation on SpacetimeDB, TypeScript canvas client,
authoritative 20 TPS with a deliberate one-second command delay. Played on the
four-spawn `crossfire` map (3200).

Since the last handover, in order (HANDOFF steps 17-20):

- **Shields and the Network power field** (17): relays, drifters trained at any
  powered structure, death restoration, teleport. Shields vary by kind, SC2
  style, and teleport has a 30s cooldown (both 2026-09-25).
- **Faction armies** (18): every faction trains only its own fighter, raider
  and anti-structure unit. Industrial soldier/scout/siege, Network
  sentinel/skimmer/lancer, Organic swarmer/spitter/crusher. Names confirmed.
- **Practice opponent picker and held first push** (19): the practice bot plays
  any faction, and keeps its army home until 3:00.
- **Command-card construction** (20, Increment J): buildings are placed from
  the Build tab and raise themselves. No worker builds, nothing can be
  cancelled or interrupted, and build radius still limits placement. Also: unit
  cap 120, a second barracks for the bot, a client-side map-hash check, and a
  fix for workers freezing behind their own hub.

**Demoted:** fog of war and the private-state experiment it needs (may never be
built); the Industrial autonomous extractor (Increment F).

## Before anything else: a person has to play it

Steps 18-20 were played only by Playwright scripts and bot-vs-bot runs. The
scripts are weak players: they never survived the bot's first push. Three
things only a person can settle:

1. Whether the held push (3:00, but 29-36 units) is survivable. Softening
   options are recorded under step 19: cap the army during the hold, send a
   partial first wave, or keep heavy units home.
2. Whether the unit drawings read at default zoom. Owner colour currently
   does most of the work.
3. Whether command-card construction feels right. It changes the opening:
   no mining time is lost to building any more.

## The next chunky steps

In recommended order. Each is a full increment: server, client, bot, tests,
a scripted play, then an entry in HANDOFF.md.

### 1. Behaviour presets: deferred by the author

**Deferred (2026-09-25).** The author moved presets to one of the last things
built: how players create presets and their own strategies needs more thought.
Players micro everything themselves for now. The design notes are unchanged
([COMMANDS-AND-BEHAVIORS.md](COMMANDS-AND-BEHAVIORS.md)); see
[DECISIONS.md](DECISIONS.md).

Settled at the same time: firing on the move becomes a **per-kind stat** (which
kinds stop to fire is still open), and `move` keeps firing at anything in range,
like SC2's attack-move. A plain "only move and run" order may come later.

### 2. Primary-hub victory: implemented (HANDOFF step 21)

Settled and built 2026-09-25: completed hubs only, same-tick draw, outposts of
every faction count. The text below is the original brief.


Elimination is still "your HQ died". With outposts in every build order, the
design's proposed rule matters now: a player is out when they have lost every
**completed** hub, and a same-tick last-hub loss on both sides is a draw
([GAME-DESIGN.md](GAME-DESIGN.md), "Victory"). Small server change, but
the practice bot, the score screen and the "Your HQ has been destroyed" refusal
all assume the one-HQ rule. It also changes how the bot should attack (hubs,
not the HQ).

*Ask the author first:* confirm the proposed rule, and whether an Organic
outpost counts as a hub for victory, since it already counts for training.

### 3. First faction abilities

The author confirmed abilities come after stats. The design names the
identity-critical ones: Industrial **smoke** and **retreat** (and outpost
income suppression by damage), Network **recall** (shield-funded in the
reference game), Organic **temporary terrain** and territory-bound bonuses.
Build the ability/status primitive once (charges or energy, cooldown,
targeting, a delayed cast, command-card button, bot usage), then one ability
per faction. Smoke only blocks sight if fog exists, so it needs its own
definition now that fog is demoted.

*Ask the author first:* which one ability per faction to start with, and what
smoke should do in a game without fog.

### 4. Movement and load at 120 units

The cap is now 120 per player. The last tick measurement at 120 was ~26-28ms
p95 on a busy machine, against a 25ms budget. Before large armies become
normal: rerun `bench_load` on an idle machine, measure group movement through
crossfire's chokes, and fix the worst jam. This is the M1 "movement" and
"tick/load" experiments. The routing fix in step 20 shows that stalls still
hide in `navigation::advance`. A scenario harness that walks groups through
every choke would catch the next one.

### 5. Renderer pilot (Three.js)

M1's renderer experiment: one original animated unit, structure, deposit,
terrain and zone in Three.js, readable at target zoom within a frame budget.
The canvas client's small silhouettes are the current readability limit.
Independent of 1-4 and can run in parallel with them.
