# Handover — 2026-09-23

Written for whoever picks this up next, human or agent, assuming no memory of
this session. [HANDOFF.md](HANDOFF.md) holds the per-step evidence log; this is
the orientation on top of it.

## What this project is now

An original browser RTS converging on the Honey Badger mod's *strategic*
identity, not its SC2 roster. Rust simulation on SpacetimeDB, TypeScript client,
authoritative 20 TPS ticks with a deliberate one-second command delay.

It is playable. Publish, open the client, and you get a four-spawn melee map,
three factions with genuinely different mining, tech-gated production, and a
post-match score screen with graphs.

## Run it

```
npm run server:start                                   # SpacetimeDB on :3000
spacetime publish --server http://127.0.0.1:3000 --module-path server --yes <fresh-db>
npm run dev                                            # Vite on :5173
```

Then open `http://127.0.0.1:5173/?database=<fresh-db>`.

**Use a fresh database name** whenever the schema changed — it changes often,
and publishing in place over an old one fails. Old databases are disposable.
Nothing is committed and nothing is deployed anywhere.

Gates, in the order worth running them:

| Command | Covers |
| --- | --- |
| `cargo test --manifest-path server/core/Cargo.toml` | 135 tests, the real safety net |
| `npm run test:client` | 37 tests |
| `npm run typecheck`, `npm run build` | types and bundle |
| `cargo check --manifest-path server/Cargo.toml --target wasm32-unknown-unknown` | the module actually compiling |
| `STDB_DATABASE=<db> npx playwright test` | 4 tests, needs both servers up |
| `STDB_DATABASE=<db> npx tsx --test tests/integration.test.ts` | 12 tests, real server, ~3 min |
| `cargo run --release --manifest-path server/core/Cargo.toml --example bench_load` | tick cost |

After a schema change: `npm run generate` to regenerate bindings. Never
hand-edit `src/bindings/`.

## What exists, in one pass

**Map.** `crossfire`, 3200x3200, four spawns, 152 deposits, four-fold
rotational symmetry. Four bases per player — main, natural, third, and a shared
edge base equidistant from two mains. **Catalyst is per-base like SC2 gas**, and
the centre carries no resources at all: it is fought over for position, not
income. Matches resolve their map through `Room.map_id`, while `default_map()`
stays the small `skirmish` map so simulation tests remain fast and
coordinate-stable.

**Economy.** Two currencies. Material funds expansion, labour and basic army;
Catalyst gates technology and specialists, and specialists cost both. Army
deaths refund 50%. An opening stipend pays 200 material/minute for 90 seconds
then 100/minute for 90 more — **free income with no deposit drain**, worth
knowing before reading any early-game number.

**Three factions, distinguished first by how they mine.** Industrial `worker`
mines and returns. Network `drifter` credits in place and never returns.
Organic `harvester` is free but limited by hub stock and cannot fight. Each
faction opens with two of its own labour, already gathering the nearest
material deposit from tick 0.

**Tech gating.** A hub trains labour and nothing else. Soldiers and scouts come
from a barracks, siege from a factory, and both factory and lab need a completed
barracks.

**Zones.** The primitive plus the Industrial `sensor` tower — 450 radius, +30%
movement, owner only. Zones are derived from their sources every tick, so there
is no removal path and a dead source cannot leave a field behind.

Organic `creep` is the exception: one stored disc per hub (HQ 360, outpost
300) in the `creep_patch` table, growing while its source lives and lingering
then receding after it dies. It slows its owner's harvesters to 0.6x off creep
and spawns short-lived brood/brute when the owner's units die on it. See
[ZONES.md](ZONES.md).

**Score screen.** A `match_sample` time series every 100 ticks plus a final row
at the end, drawn as a roster and charts for income, army value, unspent balance
and labour.

## The rules that keep this honest

Break these and the design quietly stops meaning anything.

1. **Zones must not collapse into one flag.** A zone declares which of six
   concepts it participates in — movement, sight, projectiles, connectivity,
   economy/survival, combat/death — and a test enumerates `ZoneConcept::ALL` to
   prove the sensor field touches movement and nothing else. If creep ever
   starts blocking sight "because it looks like it should", that separation has
   failed.
2. **Income means mined income.** `collected` excludes the stipend and refunds,
   and is asserted against real deposit drain minus cargo still in transit. Do
   not fold free money into an economy graph.
3. **`killed` is last-hit attribution** and the UI says so. Do not present it as
   a measure of who did the damage.
4. **Nothing about fog, smoke or hidden scouting** may be built until the
   experiment in [EXPERIMENT-C-PRIVATE-STATE.md](EXPERIMENT-C-PRIVATE-STATE.md)
   reports. Every table is public today, so a custom client reads the whole
   database. Client-side filtering is not an acceptable fallback.
5. **Every balance number is experimental.** None of it is playtested.

## Traps this session actually fell into

Each cost real time. They are the reason to check rather than assume.

- **Stale extents.** The map grew from 1600 to 3200 and hardcoded `1584`,
  `1540` and `800` survived in several places — most recently in the order
  dispatch, which silently forced every move and rally into the top-left
  quarter of the map. If something is confined to one quadrant, grep those
  numbers first.
- **The clock was 19% slow.** The tick stepped once per scheduler wake, and the
  host does not deliver the period you request. Every measurement taken before
  that fix was against 16.2 TPS instead of 20. It now advances by elapsed wall
  time.
- **A unit could freeze forever** against a terrain corner: movement proposed a
  step into a clearance margin, the end-of-tick rule reverted it, and the next
  tick computed the identical step. Fixed, with a regression test that emulates
  the revert — without that emulation the test passes against the bug.
- **Benchmarks exclude database persistence.** Core simulation is cheap: 0.43ms
  at low unit counts against a 50ms tick. The real cost is in
  `load_world`/`save_world` row traffic, which nothing has measured.
- **Test failures were usually the test.** Clearing units removed the HQ that
  orders require; a one-player world wins instantly; two soldiers in one world
  shoot each other; a unit spawned on top of a building gets shoved clear by
  separation and reads as 26% faster. Suspect the test first.

## Known open issues

- **The practice bot is fixed for tech gating** (2026-09-24). Hubs are only
  asked for labour, checked through `canProduce`; barracks and factory train
  the army. It had never placed a barracks on crossfire — every hardcoded offset
  was obstructed — and now ring-searches 220–460 from the HQ. Live three-way:
  barracks at 10–11s for all factions, four army by 35–60s, no hub refusals.
  Not acted on: Network was eliminated before 120s in both runs (balance or
  combat, not the bot); Industrial floats ~3.4k material at 180s; every player
  opens with its labour **plus one soldier** — confirm that is intended.
- **Creep's client rendering is done and validated 2026-09-24.** The
  simulation, persistence and client are all verified (135 Rust tests, client
  42/42, integration 12/12, browser 4/4). Still unverified: a brute has never
  been seen on screen, a brood has not been given orders through the UI, no
  browser test covers creep, and the creep tint is faint at default zoom (the
  author's judgement, not measured).
- **Creep's tick cost is unquoted.** The bench could not separate it from noise
  on a busy machine; rerun `bench_load` on an idle one before comparing it to
  the 9.1/18.4ms zone baseline. The per-tick `creep_patch` read is unmeasured.
- The client cannot compare `map_hash`; the column exists but no negotiation
  does. `validate_map` does not print the hash.
- `tests/integration.test.ts` mirrors the stipend formula so its balance
  assertions stay exact. If the Rust constants move, that helper must move too.
- `quadrille` is a superseded melee map kept as a 3200 test fixture. It still
  has catalyst in the centre and is not played.

## Where to go next

In the author's stated priority order. Zones and per-faction mechanics rank far
above everything else, and the autonomous extractor is explicitly **low value**
— do not pick it up because it looks cheap.

Organic creep is complete — server, persistence and client rendering — and
validated 2026-09-24.

1. **Shields**, a second health pool. The Network power field cannot exist
   without it.
2. **The Network power field** — worker creation at any structure inside it,
   faster shield regeneration, a dying unit restoring shields to nearby
   friendlies scaling with its total health, and teleport from anywhere in the
   field to anywhere else in it.
3. **Command-card construction.** Buildings are ordered from the card and raise
   themselves with no worker involved; the reference game is closer to Command &
   Conquer than StarCraft here. Three questions need answering first and are not
   guessable: refund terms on cancelling an unfinished building, whether
   construction can be interrupted now nothing is attached to it, and whether
   build radius still means anything.

Deferred by the author, with reasons recorded: optimization — the zone layer
costs +25% on p95, and 120 units per player is over budget on the 3200 map — and
`MAX_UNITS`, where 120 is measured-safe on the small map and 240 is not.
